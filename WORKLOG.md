# WORKLOG — EduHub (ВКР, текущий этап)

## 0) Быстрый старт с любого ПК (обязательно после git pull)

1. Переключиться на **актуальную рабочую ветку** (уточнять у автора; ранее активно велась `prediploma-journal`):
   - `git checkout <ветка>`
   - `git pull`
2. Поднять окружение: активировать `.venv`
3. Синхронизировать БД с кодом: `python manage.py migrate`
4. Проверка запуска: `python manage.py runserver`

## 1) Цель текущего этапа (ВКР)

- Довести **основной сквозной сценарий** и оформить **отличимый вклад** (коммуникация педагог↔родитель, правки данных ребёнка родителем, документооборот/отчёты — в объёме, согласованном с текстом ВКР).
- Параллельно вести **текст ВКР** (черновик в `reports/vkr/`), синхронизируя утверждения с кодом.
- Минимально необходимое **тестирование** критического пути; **деплой** — по остатку времени как демонстрация зрелости.

## 2) Текущая рабочая ветка

Уточнить при старте задачи (история: `prediploma-journal`).

## 3) Что уже сделано ранее (прототип / преддиплом — кратко)

- Сквозной контур: заявки, одобрение/отклонение, связи родитель–ребёнок, зачисление, журнал посещаемости.
- Роли, кабинеты, аутентификация и выбор роли (`users`), профили и сценарии `accounts`, расписание и группы `schedule`.
- Поля договора у родителя (`address`, `passport`), страницы менеджера (расписание, отчёты), дашборд педагога.
- Материалы практик и ВКР: **`reports/tech/`**, **`reports/prediploma/`**, **`reports/vkr/`**, нормативка **`reports/guidelines/`** (см. [PROJECT_SUMMARY.md](PROJECT_SUMMARY.md)).

## 4) Что сейчас в работе

- Текст и структура ВКР (`reports/vkr/`), адаптация удачных формулировок из преддипломы без путаницы «практика vs ВКР».

## 5) Следующий микро-шаг (ближайший)

- Зафиксировать в тексте ВКР **один тезис отличия** и список фич под него (MVP на оставшийся срок).
- В коде: первый инкремент под этот тезис (маленький, проверяемый end-to-end).

## 6) После следующего шага

- Обновить разделы «Реализация / результаты» в ВКР и скриншоты.
- При наличии времени: автотесты на критический путь, черновой деплой.

## 7) Ограничения на этапе ВКР

- Не блокировать текст ради **крупного рефакторинга** — см. [REFACTORING.md](REFACTORING.md).
- Делать маленькими шагами: одно изменение → проверка сценария → коммит.

## 8) Коммит-стиль

Conventional Commits: `feat(...)`, `fix(...)`, `refactor(...)`, `docs(...)`.

Примеры:

- `feat(parent): add contract fields to parent profile`
- `feat(parent): add parent profile edit form`
- `fix(manager): show actions only for new applications`

## 9) Быстрый чек перед пушем

- `git status`
- `python manage.py migrate` (при изменениях моделей)
- `python manage.py runserver` (ручная проверка сценария)
- `git add` / `git commit` / `git push`
